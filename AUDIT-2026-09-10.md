## Deslop Applied

Repo had already received three cleanup passes (`0de5939`, `e1b0cd2`, `88f7eae`), so only two genuinely dead items remained; both are behavior-preserving by construction.

- `tailwind.config.js:13` — removed the `neon-green` theme token. No class derived from it (`neon-green`, `text-neon-green`, `bg-neon-green`, `border-neon-green`, …) appears anywhere in `index.html`, `src/`, or any other tracked file (verified with `grep -rn "neon-green"`), so Tailwind never emitted it and removing the token cannot change generated CSS. Confirmed by an identical post-change build artifact hash.
- `.gitignore:44` — removed the duplicate `docs/plans/` entry under "Generated documentation". The same path is already ignored at line 28; `git check-ignore -v docs/plans/foo.md` still resolves to `.gitignore:28`, so ignore semantics are unchanged.

Deliberately **not** changed (to avoid non-behavior-preserving or API-touching edits):

- `useAudioAnalyzer(audioEl, audioEl != null)` (`src/App.tsx:10`): the `enabled` argument is redundant with `audioElement != null`, and the hook's `if (!audioElement || !enabled) return;` guard is therefore partly tautological. Removing the parameter changes an exported hook's signature and its only call site → documented in Full Review instead.
- The no-op Meyda `callback` at `useAudioAnalyzer.ts:62-64` looks like dead code but is a **required** field of `MeydaAnalyzerOptions` and carries an explanatory comment; retained.
- Duplicate 4-line blob-URL revocation between `Overlay.tsx:26-29` and `Overlay.tsx:39-42` serves two distinct lifecycles (source swap vs. unmount). Extracting a helper would be a wrapper with marginal value → skipped.
- Two stray double blank lines (`src/components/TimbreCloud.tsx:75-76`, `.gitignore:36-37`): pure whitespace, no code impact → skipped to keep the diff meaningful.

## Full Review Findings

Ranked by impact (read-only; **no** changes made for these).

1. **Medium — No automated test suite.** `package.json` has no `test` script (`npm test` → `npm error Missing script: "test"`), and `CLAUDE.md` confirms "No test framework configured." The two nontrivial pieces of logic are unverified: the fixed-size shift buffer and normalization math in `src/components/TimbreCloud.tsx:43-70`, and the conditional feature publishing in `src/hooks/useAudioAnalyzer.ts:71-93`. A regression in `copyWithin(3, 0, (HISTORY_SIZE-1)*3)` or in a `mapLinear` constant would ship silently. *Recommendation:* add Vitest, unit-test the pure mapping/shift helpers (extract them if needed), and keep the React/WebGL layer on visual QA.
2. **Medium — Oversized production bundle.** `npm run build` emits `dist/assets/index-DLGFmtJG.js` at **1,181.81 kB (328.07 kB gzip)** and Vite warns "Some chunks are larger than 500 kB". Almost all of it is `three` + `@react-three/drei` + `postprocessing` pulled into one chunk. *Recommendation:* `build.rollupOptions.output.manualChunks` to split the three/fiber vendor chunk, and/or lazy-import the scene behind `React.lazy`. Perf/hygiene, not correctness.
3. **Low — `audioElement` change does not rebind the audio graph.** In `src/hooks/useAudioAnalyzer.ts:45-53`, creation is guarded by `if (!sourceRef.current)`, and `audioContextRef`/`sourceRef` are never reset or disconnected in cleanup (`:97-100`) and `ctx.close()` is never called. If the `audioElement` prop identity ever changes, the analyzer keeps reading the old element, and the `MediaElementAudioSourceNode` leaks on unmount. Currently benign because `App.tsx` holds a single stable `<audio>` element for the app's lifetime. *Recommendation:* key the refs to the current element and disconnect/close in cleanup, or make the element a stable singleton by contract.
4. **Low — Redundant `enabled` parameter.** `src/App.tsx:10` passes `audioEl != null` as `enabled`, duplicating the hook's own `audioElement != null` check (`useAudioAnalyzer.ts:31`). Public-ish API change → not modified. *Recommendation:* collapse to a single `audioElement` parameter.
5. **Low — README test/performance appendix is not reproducible.** `README.md` ("Appendix: System Test Results") asserts headless-Chrome screenshots, "Consistent 60fps", and console-log confirmation, but no script, harness, or artifact in the repo can reproduce those claims. Correlation with finding #1. *Recommendation:* either commit the harness and a sample screenshot or soften the wording to "manually verified".
6. **Low — `@types/three` shipped as a runtime dependency** (`package.json:16`) — see Security Findings. *Recommendation:* move to `devDependencies` (needs lockfile regen).
7. **Info — No CI configured.** Scan topology reports `ci: false`; lint/type/build checks are manual only. *Recommendation:* a minimal GitHub Actions job running `npm ci && npm run lint && npm run build` would enforce the gate that currently passes only by convention.

## Remaining Risks

- **No test coverage** for the buffer-shift/normalization math or the analyzer hook; all verification above proves compilation and bundling, not runtime DSP correctness. This is the largest residual risk.
- **WebGL/Web Audio behavior not exercised.** No headless browser run was performed, so the render loop, Meyda feature extraction, and the README's performance claims remain unverified in this audit.
- **Supply-chain / dependency versions not audited.** `package-lock.json` was intentionally left untouched and `npm audit` was not run (network-dependent); transitive vulnerabilities in `three`/`meyda`/`postprocessing` are out of scope of this pass.
- **`install.sh` not executed** end-to-end (would clone/install into a directory and run `npm install`); reviewed statically only.
- **Latent audio-graph lifecycle bug** (finding #3) remains unfixed because the correct fix depends on whether the `<audio>` element is intended to be stable — a design decision, documented rather than silently patched.
- `curl | bash` installer and the swallowed `git pull` error remain by design (documented).
